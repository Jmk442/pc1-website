Script · Format as Pre-Generation Structuring
Why Format Must Be Specified First

Format specification operates at a critical point in the generation pipeline: it determines the structural template before token generation begins. This is fundamentally different from reformatting after the fact — which requires complete regeneration.

When a user specifies 'present as a table with four columns,' the model's generation process is constrained to a tabular structure from the first token. The attention mechanism allocates resources to producing cell-appropriate content — concise, comparative, structured. The output is shorter, more information-dense, and more likely to be accepted on first generation.

Without format specification, the model defaults to its most probable output structure: continuous prose. Prose is the highest-entropy format — it permits the widest range of token sequences, generates the most tokens per unit of information, and is the least likely to match a user's specific structural requirements.

The default is not wrong. But the default is expensive.

🔄 Adapt — Before/After Comparison

The Difference Format Makes

Source: the Without/With Format comparison table from Chapter 7. TABLE IS CONTENT — read as spoken contrast.

Here is the contrast.

Without format: 'Explain the differences between renewable and non-renewable energy.'

The model produces five paragraphs mixing definitions, examples, and analysis. The comparisons are buried in the text. You need to read all of it to find what you need. Then you ask for it in a table. That second prompt is a full regeneration.

With format: 'Compare renewable and non-renewable energy in a table with columns for source, cost, environmental impact, and availability.'

The model produces a clean table with exactly those four columns. You can scan it in ten seconds and use it directly.

Same information. Same model. One specification — the format — determined whether it worked on the first try.

Script · The Energy Equation
Every Reformat Is a Full Regeneration

The reformatting cost is one of the most significant sources of avoidable waste in AI interaction, because it requires complete regeneration of content that was already generated correctly in substance but delivered in the wrong structure.

The original output — correct in content, wrong in format — is fully stranded. Every token generated to produce it is wasted. The retry generates a new response from scratch. Full cost. Second time.

At scale, this compounds. An organisation processing five thousand AI prompts per day with a 30 percent reformatting retry rate generates fifteen hundred unnecessary full-cost regenerations daily. That is not a rounding error. It is a structural waste pattern that format specification eliminates entirely.

Script · Format Types in Practice
Matching Format to Purpose

Effective format specification requires matching output structure to its downstream use.

A comparison task calls for a table — side-by-side columns make differences immediately visible. A process documentation task calls for numbered steps — sequential, each step actionable. An executive briefing calls for a short summary followed by structured sections — fifty words at the top, supporting detail below.

The principle is simple: think about what you are going to do with the output. That tells you the format. If you are going to scan it quickly, you need a list or a table. If you are going to read it start to finish, you need prose with clear structure. If you are going to present it, you need concise headed sections.

Specifying the format before generation is not a constraint on the AI. It is an instruction that makes the AI's output immediately usable — without the additional cost of reformatting it afterwards.
