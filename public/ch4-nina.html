Script · Context as Constraint

Context — The First Element

Context is positioned first in C.R.A.F.T. because it is the prerequisite for everything that follows. Without it, every subsequent element — role, action, format, tone — operates in a vacuum, producing output that may be technically competent but directionally wrong.

Large language models generate output by sampling from probability distributions across their entire parameter space. An uncontextualised prompt — 'write about climate' — activates competing semantic clusters spanning atmospheric science, policy, economics, biology, and geography simultaneously. The model must resolve this ambiguity probabilistically, producing outputs that are broad, hedged, and frequently misaligned with what the user actually needed.

Context operates as a pre-generation constraint mechanism. By specifying domain, audience, and parameters before the model begins generating, the user effectively prunes the inference search space. The model allocates attention to a narrower semantic region, producing outputs that are more relevant, more concise, and less likely to require regeneration.

Every token the model does not have to generate unnecessarily is electricity that does not have to be spent.

Same model. Same capability. Different input — different result.

Script · Three Dimensions

The Three Dimensions of Effective Context

Effective context has three components. Each one narrows the model's generation pathway further.

The first is domain specification. This defines the subject boundary. 'Climate' activates the entire semantic field. 'The energy consumption of hyperscale data centres and their contribution to global carbon emissions' activates a precise subset. The narrower the domain, the fewer competing token distributions the model must resolve.

The second is audience specification. This calibrates register, vocabulary complexity, and assumed knowledge. A prompt specifying 'for a policymaker with no technical background' produces fundamentally different output than one specifying 'for a peer-reviewed journal submission.' Without audience specification, the model defaults to a mid-register generalist voice that frequently satisfies neither audience.

The third is parameter specification. This defines output constraints — length, scope, inclusions, exclusions. These operate as hard boundaries on the generation process. A 200-word limit prevents the token-expensive tendency of models to over-generate when unconstrained.

Three dimensions. Each one working. Together, they transform the model's generation from probabilistic guessing into constrained precision.

Script · The Cascade

Why Context Must Come First

Context constrains everything downstream.

Role assignment without context produces a generic expert with nothing specific to address. Action specification without context produces a correctly-named but incorrectly-scoped task. Format and tone, applied to a contextless prompt, produce well-shaped outputs that miss the point entirely.

The cascade is directional. Context set correctly means every subsequent element in C.R.A.F.T. operates on an already-narrowed search space, rather than attempting to compensate for ambiguity that context should have resolved.

This is the mechanism behind C.R.A.F.T.'s compounding efficiency. Each element does not operate independently — it builds on the constraints already established. And the energy savings compound in the same direction: each element applied correctly eliminates a category of possible retry.
